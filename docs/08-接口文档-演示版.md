## 通用约定

1. **统一响应体**：所有接口返回 **`ApiResponse<T>`** = `{ code: 200, message: "操作成功", data: T }`
2. **分页响应体**：列表接口 `data` = **`PageResult<T>`** = `{ records: T[], total, page, size }`
3. **认证**：除注册 / 登录外，所有接口必须带请求头 **`Authorization: Bearer <accessToken>`**
   - 缺失 / 过期 / 已在 Redis 黑名单 → 返回 **401**（客户端应清本地 token 并跳登录页）
   - 角色不匹配（如患者访问 `/api/admin/**`、管理员访问患者接口）→ 返回 **403**
4. **金额**：一律**整数分**，字段名带 `*Fen`，前端展示需 `/100` 转成"元"。
5. **时间格式**：日期时间 `yyyy-MM-dd HH:mm:ss`（Asia/Shanghai），纯日期字段 `yyyy-MM-dd`，纯时段 `HH:mm:ss`。
6. **删除**：管理端删除一律为**逻辑删除 / 启用停用**（`enabled=0` 或 `deleted=1`），不做物理删除。

# 一、科室管理（6 接口）

---

## 1.1 患者端 · 科室树查询

- **接口地址**：`GET /api/departments/tree`
- **请求方式**：`GET`
- **请求数据类型**：无（Query 参数空）
- **响应数据类型**：`application/json`
- **接口描述**：返回**两级科室树**。`parentId=0` 为一级科室（内科 / 外科 / 妇产科 / 儿科…），其 `children` 为二级科室。仅返回 `enabled=1` 的已启用科室。结果走 **Redis 缓存**（5 分钟），科室有增删改查后缓存自动失效。

**请求参数**：

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | 示例值 |
|---|---|---|---|---|---|
| （无） |  |  |  |  |  |

**响应状态**：`200` 成功。

**响应参数**（`data` = `DepartmentTreeNode[]`）：

| 参数名称 | 参数说明 | 类型 | 示例值 |
|---|---|---|---|
| id | 科室 ID | integer(int64) | `2001` |
| code | 科室编码 | string | `MED` |
| name | 科室名称 | string | `内科` |
| description | 科室简介 | string | `心血管、呼吸、消化、神经、内分泌等内脏疾病。` |

- **接口地址**：`GET /api/slots`
- **说明**：患者端根据「科室 + 日期」查询可预约时段号源。前端通常**遍历未来 7 天分别调用**。结果仅返回 `OPEN` 且 `remainingQuota > 0` 的号源。**已缓存 5 分钟**。

**请求参数**：

| 参数 | 说明 | 必须 | 示例 |

| levelId | 号别 ID（不传查全部）| 否 | `3003` |

**响应字段（`data = SlotSummary[]`）**：

| 字段 | 说明 | 示例 |
|---|---|---|
| slotId | 号源 ID（**下单时传这个**）| `601031` |
| doctorId / doctorName | 医生 ID / 姓名快照 | `4001` / `陈明远` |
| departmentId | 二级科室 ID | `2101` |

| feeFen | 挂号费（分）| `5000` |

**请求体 & 字段（`ScheduleRule` 实体，用于 5.3 / 5.4）**：

| period | 时段：`MORNING / AFTERNOON / EVENING` | `MORNING` |
| slotsJson | 时段 JSON：`[{ "start":"08:00", "end":"08:30", "quota":4 }, ...]` | （JSON 字符串）|

# 七、挂号记录管理（9 接口）

> 最复杂的模块：患者端 6 + 管理端 3。

---

## 7.1 创建预约订单（患者端）

- **接口地址**：`POST /api/orders`
- **限流**：同一用户 5 次 / 分钟。
- **执行流程**：
  1. Redis **`SETNX` 互斥锁**防并发重复扣号
  2. 条件更新 `UPDATE schedule_slot SET remaining_quota = remaining_quota - 1 WHERE slot_id = ? AND remaining_quota > 0`
  3. 更新行数 = 0 → 返回 `409003 SLOT_SOLD_OUT`
  4. 成功 → 生成 `PENDING_PAYMENT` 订单，设置 **15 分钟支付截止期 `expiredAt`**
- **请求体（`CreateOrderRequest`）**：

| 字段 | 说明 | 必须 |
|---|---|---|
| slotId | 号源 ID（号源查询的 `slotId`）| 是 |
| contactId | 就诊人 ID | 是 |
| idempotencyKey | 幂等键（客户端 UUID，同一用户同一 key 重复提交只生成 1 笔）| 是 |

- **响应**：`data = OrderDetail`（`status` 固定 `PENDING_PAYMENT`，含 `expiredAt`）。
- **错误**：`409002` 就诊人不属于当前用户；`409003` 号源抢完；`429` 限流。

---

## 7.2 模拟支付

- **接口地址**：`POST /api/orders/{id}/pay`
- **说明**：模拟第三方支付回调。支付成功 `PENDING_PAYMENT` → `PAID`，记录 `paidAt`。重复调用**幂等**。
- **错误**：`409004` 订单已取消 / 已完成；`404` 订单不属于当前用户。

---

## 7.3 用户取消订单

- **接口地址**：`POST /api/orders/{id}/cancel`
- **行为**：归还号源（`remaining_quota + 1`），`cancelReason = USER`。
- **错误**：`409004` 取消已终态。

---

## 7.4 我的挂号记录

- **接口地址**：`GET /api/orders`
- **请求参数**：`status`（可选，枚举四状态）/ `page/size`

# 八、登录注册与认证鉴权（6 接口）

> 你最开始要求合并的 3 组 → 现在是一个「登录注册与认证鉴权」分组，**6 个接口全部归在一起**。

---

## 8.1 患者注册

- **接口地址**：`POST /api/app/auth/register`
- **请求体**：`{ phone, password(8-64), nickname }`
- **行为**：成功后**自动登录**，直接返回 `LoginResponse`（含 JWT）。
- **错误**：`409001` 手机号已注册。

---

## 8.2 患者登录

- **接口地址**：`POST /api/app/auth/login`
- **请求体**：`{ phone, password }`
- **行为**：`账号不存在` 与 `密码错误` 统一返回 `401 账号或密码错误`（避免枚举用户）。

---

## 8.3 患者登出

- **接口地址**：`POST /api/app/auth/logout`
- **需要 Header `Authorization: Bearer <token>`**。
- **行为**：将当前 Token 的 `jti` 加入 **Redis 黑名单**直到其自然过期。重复调用第二次起返回 401。

---

## 8.4 管理员登录

- **接口地址**：`POST /api/admin/auth/login`
- **请求体**：`{ username, password }`
- **默认账号**：`admin / admin123`（seed 中创建）。

---

## 8.5 管理员登出

- **接口地址**：`POST /api/admin/auth/logout`
- **同 8.3**：Token 加入 Redis 黑名单；需 `ADMIN` 角色。

---

## 8.6 查询当前登录用户（患者 / 管理员通用）

- **接口地址**：`GET /api/me`
- **响应**：`data = LoginUser = { userId, userType, jti }`
- **用法**：App 冷启动 / 刷新页面 → 先调这个接口判断当前登录态；返回 401 表示要重新登录。
