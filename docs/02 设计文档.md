# 02 设计文档

## 1\. UI整体设计规范

本系统分为Web管理员端与鸿蒙患者端，两端采用差异化设计风格，贴合使用场景与用户群体，统一遵循简洁、轻量化、医疗风设计原则，无冗余视觉元素，保证操作高效。

- **Web管理员端**：基于Element Plus组件库开发，采用蓝白医疗主色调，风格简洁正式，以表格、表单、弹窗为核心视觉载体，适配后台数据管理场景。

- **鸿蒙患者端**：基于ArkUI声明式开发，采用轻量化移动端设计，卡片式布局、底部Tab导航，界面柔和适配手机端操作习惯，聚焦用户就医体验。

## 2\. Web管理员端UI页面设计

管理员端共6个核心页面，覆盖所有后台管理功能，页面布局统一为「左侧导航\+顶部统计/操作区\+主体数据区」结构：

### 2\.1 登录页

整体采用左右分栏布局，左侧展示医院品牌医疗插画，强化医疗行业属性；右侧为居中登录表单，包含账号、密码输入框及登录按钮，整体蓝白配色，界面简洁清爽，无多余装饰，适配后台登录场景。

### 2\.2 首页仪表盘

固定左侧全局导航菜单，顶部展示系统核心数据统计卡片，包含今日预约数、在院医生数、科室总数、平台用户数四大核心指标；页面下方分为两大模块，左侧展示预约趋势可视化图表，右侧展示最新预约记录列表，直观呈现平台运营数据。

### 2\.3 科室管理页

页面顶部设置搜索框、新增科室按钮；主体为科室数据表格，展示科室名称、描述、排序号、操作列；新增、编辑操作均通过弹窗表单实现，弹窗布局规整，表单字段清晰，支持实时提交刷新表格数据。

### 2\.4 医生管理页

顶部支持按科室筛选数据，配置新增医生按钮；主体数据表格展示医生姓名、所属科室、职称、个人简介等完整信息；支持单条数据编辑、删除操作，交互逻辑与科室管理页统一，保证后台操作一致性。

### 2\.5 排班管理页

顶部支持按医生、出诊日期双向筛选，配置新增排班按钮；表格核心展示医生、出诊日期、时间段、总号源、剩余号源、挂号费关键字段，数据一目了然，方便管理员配置与核对排班信息。

### 2\.6 预约管理页

顶部支持按预约状态筛选、关键词搜索；表格展示全量预约记录，通过不同颜色标签区分「已预约/已取消/已完成」三种状态；支持查看预约详情、强制取消预约操作，状态可视化程度高，便于订单管控。

## 3\. 鸿蒙患者端UI页面设计

鸿蒙端共4个核心页面，采用底部Tab导航统一切换，页面风格轻量化、年轻化，适配移动端单手操作，所有页面数据均通过调用后端接口动态渲染。

### 3\.1 首页

页面顶部设置全局搜索栏，支持模糊搜索科室、医生；搜索栏下方为公告轮播图，自动滚动展示医院通知；中部为8科室图标网格入口，整齐排布、点击便捷；下方为推荐医生卡片列表，展示核心医生信息；底部固定Tab导航栏，切换四大核心页面。

### 3\.2 预约页（核心页面）

页面顶部配置可视化步骤指示器，清晰展示预约四步流程，当前步骤高亮提示；中部动态加载科室、医生、排班数据，采用卡片式展示医生头像、姓名、职称、剩余号源等关键信息；页面底部固定「下一步/确认预约」操作按钮，引导用户完成预约流程，操作路径清晰。

### 3\.3 AI管家页

采用经典聊天对话界面布局，上方为对话展示区，展示用户提问与AI回复记录；页面底部固定输入框与发送按钮，支持用户输入症状描述发起咨询；界面简洁干净，聚焦医患智能咨询核心场景。

### 3\.4 我的页

页面顶部展示用户个人信息卡片，包含头像、姓名、手机号；中部为功能菜单列表，包含我的预约、就诊人管理、系统设置等入口；下方展示最近预约记录快捷卡片，方便用户快速查看、管理个人预约订单。

## 4\. 系统整体架构设计

### 4\.1 架构模式

系统采用**前后端分离架构**，三端独立部署、统一后端服务支撑，Web管理端、鸿蒙移动端均不直接操作数据库，所有数据交互通过后端标准化RESTful接口完成，彻底解耦前端展示与后端业务逻辑。

### 4\.2 三层架构整体拆分

#### 4\.2\.1 客户端层（展示层）

包含两大终端，仅负责页面渲染、用户交互、参数传递，无任何业务逻辑与数据处理能力：

- Web管理端：Vue3\+Element Plus，实现后台数据管理页面展示与操作

- 鸿蒙患者端：ArkTS\+ArkUI，实现移动端患者服务页面展示与交互

#### 4\.2\.2 服务端层（业务层）

基于SpringBoot搭建后端核心服务，采用经典分层架构，各司其职，保证代码高内聚、低耦合，分层明细如下：

- **Controller接口层**：接收前端/鸿蒙端的HTTP请求，接收参数、调用业务服务、统一返回JSON格式数据，是前后端交互的唯一入口

- **Service业务层**：处理系统核心业务逻辑，包含号源校验、预约流程、数据联动、事务控制等核心规则

- **Mapper数据访问层**：直接对接数据库，负责数据增删改查操作，基于MyBatis\-Plus简化数据库操作

- **通用配置层**：包含跨域配置、缓存配置、消息队列配置、统一返回结果、工具类等全局通用能力

#### 4\.2\.3 数据层（存储层）

包含数据库与中间件，负责系统所有数据持久化与缓存处理：

- MySQL8：持久化存储科室、医生、患者、排班、预约记录所有核心业务数据

- Redis：缓存热点数据、用户登录Token，减轻数据库压力，提升系统响应速度

- RocketMQ：异步处理消息通知，解耦核心业务与通知业务，提升系统并发能力

### 4\.3 核心技术架构优势

- 前后端完全分离，三端共用一套后端接口，减少重复开发，提升开发效率

- 分层架构清晰，业务逻辑、数据操作、接口展示完全隔离，便于迭代维护、问题排查

- 引入缓存与消息队列，解决高并发场景下的系统卡顿、阻塞问题，保证系统稳定性

- 统一接口返回格式，标准化数据交互，降低前后端联调成本

# 03 数据库设计

## 1\. 数据库整体设计说明

本系统基于MySQL8设计5张核心业务数据表，覆盖患者、科室、医生、排班、预约五大核心业务，表之间通过外键关联，保证数据完整性与关联性；所有核心业务表支持逻辑删除，保留历史数据，便于数据追溯与统计。

## 2\. 核心数据表结构设计

### 2\.1 患者用户表（patient）

存储所有注册患者的账号及个人基础信息

|字段名|数据类型|是否主键|字段说明|
|---|---|---|---|
|id|bigint|是（自增）|用户唯一ID|
|name|varchar\(50\)|否|患者姓名|
|phone|varchar\(20\)|否（唯一）|登录手机号，唯一不可重复|
|password|varchar\(100\)|否|加密存储的登录密码|
|gender|tinyint|否|性别：0\-女，1\-男，默认1|
|age|int|否|患者年龄，默认0|
|id\_card|varchar\(30\)|否|身份证号（可选）|
|create\_time|datetime|否|账号注册时间，默认当前时间|

### 2\.2 科室表（department）

存储医院所有就诊科室信息，关联医生表

|字段名|数据类型|是否主键|字段说明|
|---|---|---|---|
|id|bigint|是（自增）|科室唯一ID|
|name|varchar\(50\)|否|科室名称（唯一）|
|description|varchar\(255\)|否|科室功能、诊疗范围描述|
|sort|int|否|科室排序序号，控制页面展示顺序|

### 2\.3 医生表（doctor）

存储所有出诊医生信息，关联科室表

|字段名|数据类型|是否主键|字段说明|
|---|---|---|---|
|id|bigint|是（自增）|医生唯一ID|
|name|varchar\(50\)|否|医生姓名|
|department\_id|bigint|否|所属科室ID（外键关联科室表）|
|title|varchar\(50\)|否|医生职称（主任医师/副主任医师等）|
|intro|varchar\(500\)|否|医生个人简介、擅长诊疗方向|
|avatar|varchar\(255\)|否|医生头像图片存储地址|

### 2\.4 医生排班表（schedule）

存储医生每日出诊排班、号源、费用信息，是预约业务的核心基础表

|字段名|数据类型|是否主键|字段说明|
|---|---|---|---|
|id|bigint|是（自增）|排班唯一ID|
|doctor\_id|bigint|否|关联医生ID（外键关联医生表）|
|work\_date|date|否|医生出诊日期|
|time\_slot|varchar\(20\)|否|出诊时间段（上午/下午）|
|total\_count|int|否|当前排班总号源数|
|remaining\_count|int|否|当前排班剩余可预约号源数|
|price|decimal\(10,2\)|否|本次排班挂号费用|

### 2\.5 预约记录表（appointment）

存储患者所有预约订单数据，关联患者表、排班表，记录预约全流程信息

|字段名|数据类型|是否主键|字段说明|
|---|---|---|---|
|id|bigint|是（自增）|预约订单唯一ID|
|patient\_id|bigint|否|患者ID（外键关联患者表）|
|schedule\_id|bigint|否|排班ID（外键关联排班表）|
|status|tinyint|否|订单状态：0\-已预约，1\-已取消，2\-已完成|
|create\_time|datetime|否|订单预约创建时间|
|cancel\_time|datetime|否|订单取消时间（未取消则为空）|

## 3\. 数据库建表SQL语句

```sql
-- 创建数据库并指定字符集
CREATE DATABASE IF NOT EXISTS hospital DEFAULT CHARACTER SET utf8mb4;
USE hospital;

-- 1. 患者用户表
CREATE TABLE patient (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
  name VARCHAR(50) NOT NULL COMMENT '姓名',
  phone VARCHAR(20) NOT NULL UNIQUE COMMENT '手机号',
  password VARCHAR(100) NOT NULL COMMENT '密码',
  gender TINYINT DEFAULT 1 COMMENT '性别 0女1男',
  age INT DEFAULT 0 COMMENT '年龄',
  id_card VARCHAR(30) COMMENT '身份证号',
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '注册时间'
) COMMENT='患者表';

-- 2. 科室表
CREATE TABLE department (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '科室ID',
  name VARCHAR(50) NOT NULL COMMENT '科室名称',
  description VARCHAR(255) COMMENT '科室描述',
  sort INT DEFAULT 0 COMMENT '排序'
) COMMENT='科室表';

-- 3. 医生表
CREATE TABLE doctor (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '医生ID',
  name VARCHAR(50) NOT NULL COMMENT '姓名',
  department_id BIGINT NOT NULL COMMENT '所属科室ID',
  title VARCHAR(50) COMMENT '职称',
  intro VARCHAR(500) COMMENT '简介',
  avatar VARCHAR(255) COMMENT '头像'
) COMMENT='医生表';

-- 4. 排班表
CREATE TABLE schedule (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '排班ID',
  doctor_id BIGINT NOT NULL COMMENT '医生ID',
  work_date DATE NOT NULL COMMENT '出诊日期',
  time_slot VARCHAR(20) NOT NULL COMMENT '时间段',
  total_count INT DEFAULT 20 COMMENT '总号源',
  remaining_count INT DEFAULT 20 COMMENT '剩余号源',
  price DECIMAL(10,2) DEFAULT 0.00 COMMENT '挂号费'
) COMMENT='排班表';

-- 5. 预约记录表
CREATE TABLE appointment (
  id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '预约ID',
  patient_id BIGINT NOT NULL COMMENT '患者ID',
  schedule_id BIGINT NOT NULL COMMENT '排班ID',
  status TINYINT DEFAULT 0 COMMENT '0已预约，1已取消，2已完成',
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '预约时间',
  cancel_time DATETIME COMMENT '取消时间'
) COMMENT='预约记录表';
```

## 4\. 数据关联关系说明

- **科室与医生**：一对多关系，一个科室对应多名医生，一名医生仅归属一个科室

- **医生与排班**：一对多关系，一名医生可生成多条不同日期、时间段的排班记录

- **患者与预约记录**：一对多关系，一名患者可生成多条预约订单

- **排班与预约记录**：一对多关系，一条排班记录可对应多条患者预约订单
