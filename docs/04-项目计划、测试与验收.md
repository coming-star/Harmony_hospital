# 项目计划、测试与验收

## 1. 分工

| 角色 | 主要产出 | 协作责任 |
| --- | --- | --- |
| 组长/测试文档 | 需求基线、原型协调、测试用例、验收报告、答辩材料 | 每日风险跟踪、接口联调验收、演示数据准备。 |
| 后端工程师 | 数据库、Spring Boot API、鉴权、预约一致性、Redis/MQ | 发布 OpenAPI/接口示例，提供初始化脚本。 |
| Web 前端工程师 | 管理端全部核心页面、状态管理、接口联调 | 固化后台表单与分页交互。 |
| 鸿蒙端工程师 | App 页面、登录态、预约闭环、AI 页面 | 处理移动端加载、错误与登录拦截。 |

## 2. 10 天里程碑

| 天数 | 目标 | 可验证产物 |
| --- | --- | --- |
| D1 | 环境与基线 | Git 规范、JDK/Node/MySQL/Redis/RocketMQ 启动、建库脚本、接口约定、原型确认。 |
| D2 | 基础能力 | 用户/管理员登录注册、JWT、后台框架、App 登录注册与 Tab 骨架。 |
| D3 | 基础资料 | 科室、号别、医生 CRUD；App 科室树和医生列表可读取。 |
| D4 | 排班与号源 | 排班规则 CRUD、未来 7 天号源生成、App 日期/号别筛选。 |
| D5 | 预约创建 | 就诊人 CRUD、下单校验与原子扣号、待支付订单。 |
| D6 | 闭环联调 | 模拟支付、取消/超时释放、后台挂号记录、工作台统计。 |
| D7 | AI 与体验 | AI 登录拦截、会话和查询/预约草稿；页面空态、加载态、错误提示。 |
| D8 | 集成冻结 | 全链路回归、并发扣号测试、缺陷修复、演示脚本。 |
| D9 | 测试与答辩 | 测试报告、部署说明、PPT、答辩演练。 |
| D10 | 答辩/面试 | 演示、问答、代码走查与材料归档。 |

每日结束前合并可运行代码；D6 后只接收 P0 缺陷，新增功能需经组长评估。

## 3. 验收测试清单

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| T01 | 注册重复手机号 | 拒绝注册并给出明确提示；密码不回传。 |
| T02 | 未登录访问 AI/下单 | App 引导登录；后端返回 401。 |
| T03 | 绑定多个就诊人 | 可新增多位；相同账号身份证重复被拒绝；列表仅显示本人数据。 |
| T04 | 预约筛选 | 更换日期、科室、号别后，只显示匹配且有余号的可用时段。 |
| T05 | 正常预约 | 选择就诊人后生成待支付订单，余号减 1；支付后订单为已支付。 |
| T06 | 同时抢最后一个号 | 两个并发请求仅一单成功，余号为 0 且不为负。 |
| T07 | 重复提交/支付 | 同一请求重试只生成一笔有效订单；重复支付不改变金额或状态。 |
| T08 | 超时/取消 | 待支付订单取消或超时后状态正确，余号仅归还一次。 |
| T09 | 后台逻辑删除 | 删除后列表默认不见，数据库记录保留；被预约引用的数据禁止删除并提示停用。 |
| T10 | AI 预约建议 | AI 给出可验证的号源信息或预约草稿，但不会直接创建已支付订单。 |

## 4. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 10 天功能过多 | 以 P0 闭环优先；AI、轮播和消息通知按 P1 降级。 |
| 前后端字段不一致 | D1 确认 API 文档、枚举和样例；后端变更先更新契约。 |
| 号源超卖 | 服务端条件更新+事务+幂等状态机；测试并发最后一号。 |
| MQ/Redis 本机搭建耗时 | D1 完成 Docker/本地启动验证；P0 允许定时任务替代超时消息，但须保留接口。 |
| 外部 AI/支付不可用 | 使用 Mock 支付和可配置模型网关；保留清晰的降级提示与演示数据。 |
| 隐私泄露 | 身份证加密/哈希、接口脱敏、密钥不进 Git、日志脱敏。 |

## 5. 提交前检查

- 可从空数据库执行建表与种子数据脚本，生成至少 7 天演示号源。
- 三端分别按 README 启动；环境变量有 `.env.example`，无真实密钥提交。
- 接口异常统一、枚举一致，重要接口有成功与失败样例。
- 完成上述 T01–T10，记录测试日期、结果、缺陷与修复版本。
- 准备两个患者账号、至少三位医生、多个科室/号别和可预约时段，保证答辩现场可复现。
