# 东软云医院挂号预约系统 · 后端设计文档

> 技术栈：SpringBoot 3 + JDK 17 + MyBatis-Plus + MySQL 8 + Redis + RocketMQ + JWT + Knife4j
> 数据表：department 科室 / doctor 医生 / user 用户 / patient 就诊人 / user_patient 绑定 / schedule 排班 / appointment 预约 / pay_order 支付 / refund_log 退费 / dict 字典 / audit_log 审计

---

## 第一步：搭建 SpringBoot3 脚手架

**目标**：项目可正常启动，Knife4j 接口文档可用。

1. 创建 Maven 工程 `hospital-backend`，JDK 17，SpringBoot 3.x：
   - `spring-boot-starter-web`、`spring-boot-starter-validation`
   - `mybatis-plus-boot-starter`（3.5.x）、`mysql-connector-j`
   - `spring-boot-starter-data-redis`、`rocketmq-spring-boot-starter`
   - `jjwt-api/impl/jackson`、`knife4j-openapi3-jakarta-spring-boot-starter`（4.x）、`lombok`
2. 配置 `application.yml`：数据源（hospital 库）、Redis、RocketMQ（NameServer）、端口 `8080`。
3. 启动类 `HospitalApplication.java`，确认含 `@MapperScan("com.neusoft.hospital.mapper")`。
4. 配置 Knife4j（分组：用户端 / 管理端）。
5. 验证：启动无报错，Knife4j 文档页可访问。

## 第三步：登录 & 注册模块（user 表）

完整闭环遵循分层：**Entity → Mapper → Service（单元测试） → Controller**

1. **Entity**：`User.java`，配置 `@TableName("user")`、`@TableId(type = IdType.AUTO)`、`@TableLogic`、`@Version`、Lombok 注解。
2. **Mapper**：`UserMapper.java`，继承 `BaseMapper<User>`。
3. **Service 层**
   - 接口 `UserService.java`；实现类 `UserServiceImpl.java`：
     - `sendSmsCode(phone)`：验证码写 Redis（`sms:code:{phone}`，5 分钟；开发期用固定模拟码，生产接短信通道）；
     - `loginBySms(phone, code)`：校验验证码 → **未注册自动注册**（创建 user + 默认"本人"patient + user_patient 绑定）→ 生成 JWT；
     - `loginByPassword(username, password)`：管理员账号密码登录，BCrypt 校验，生成 JWT；
     - `logout(userId)`：删除 Redis 登录态；
     - `getUserInfo(userId)`：个人信息。
4. **JUnit5 单元测试**（只测 Service 层）：验证码生成/校验、自动注册、JWT 签发与解析。
5. **Controller 层**：`UserController.java`，发送验证码、验证码登录、管理员登录、退出、个人信息接口。
6. **Knife4j 调试**：验证码登录返回 token 正常。

> > ⚠️ JWT 拦截器依旧保持关闭状态。

## 第八步：预约 & 支付模块（appointment + pay_order 表）⭐ 核心

完整闭环：**Entity → Mapper → Service（单元测试） → Controller + RocketMQ**

1. **Entity**：`Appointment.java`、`PayOrder.java`（均含 `@Version`）。
2. **Mapper**：`AppointmentMapper.java`、`PayOrderMapper.java`。
3. **Service 核心逻辑**：
   - `createAppointment(userId, dto)`：
     - 校验就诊人归属（须为当前用户绑定）；
     - **防重复挂号**：查询同 patient + 同 schedule 是否存在 status∈{0,1} 有效订单；
     - **预占号源**：事务内条件更新 `locked_num+1`（`(remain_num-locked_num)>0`），受影响行数=0 → 号源已满拒绝；
     - 创建 `appointment`（待支付）+ `pay_order`（待支付）；
     - 发送 **RocketMQ 延迟消息**（如 15 分钟）用于超时释放；
   - `pay(orderNo, payType)`（模拟支付）：幂等校验 → 更新 pay_order 成功 → 更新 appointment（已预约、pay_time、**生成 queue_no**）→ 扣减 `remain_num-1, locked_num-1`；
   - **超时释放消费**：延迟消息触发，订单仍为待支付 → status=2（原因=超时未支付），释放 `locked_num-1`；否则幂等忽略（与支付回调竞态用 status/version 兜底）；
   - `listMyAppointments(userId, status)`：按状态分类查询；`getAppointmentDetail(id)`。
4. **JUnit5 单元测试**：下单预占、号源已满拒绝、防重复挂号、支付扣减、超时释放幂等跑通。
5. **Controller**：创建预约、支付、支付回调（内部）、我的预约、预约详情接口。
6. **Knife4j 调试**：完整走通"下单→支付→我的预约"，观察 schedule 号源变化。

> > 开发期支付为**模拟支付**（对接微信/支付宝留接口），回调与延迟消息均做幂等处理。

## 第九步：退号退费 & 取消预约模块（refund_log 表）

完整闭环：**Entity → Mapper → Service（单元测试） → Controller**

1. **Entity**：`RefundLog.java`。
2. **Mapper**：`RefundLogMapper.java`。
3. **Service**：
   - `cancel(userId, orderNo, reason)`：
     - 待支付：status=2，释放 `locked_num-1`；
     - 已预约：status=2 + 生成 `refund_log`（待审核）+ 返还号源 `remain_num+1`（如已满恢复可约）；
     - 校验订单归属当前用户；
   - `adminForceCancel(adminId, orderNo)`：管理员强制取消（写 audit_log）；
   - `refundAudit`：退费审核（待审核 → 已退/驳回，更新 pay_order 状态）。
4. **JUnit5 单元测试**：未付取消、已付取消退费+号源回退、超时已取消订单不可再取消。
5. **Controller**：取消预约、退款审核接口。
6. **Knife4j 调试**。

# 后续步骤

## 第 8 步：启动 Vue 管理员前端开发

> 后端接口稳定之后再做前端，前端只负责调用后端已调试完毕的 API。

1. 创建 Vue3 + Element Plus 项目，封装 Axios（统一 baseUrl、token 头、统一解析 `Result`、401 跳登录）。
2. 按页面顺序开发：登录页 → 首页仪表盘 → 科室管理 → 医生管理 → 排班管理 → 预约订单管理（含退号审核）→ 用户管理。
3. 每个页面对接后端已完成接口，页面操作观察数据库数据变化。

## 第 9 步：鸿蒙端开发（ArkTS）

> 鸿蒙不直接操作数据库，全部调用后端接口，模拟器访问本机后端使用 `10.0.2.2:8080`。

1. 封装鸿蒙网络请求工具（统一 baseUrl、token 头、Result 解析）。
2. 开发页面：首页、预约挂号（一级→二级→选时间→选医生→支付）、AI 管家、我的就诊人、我的预约记录、登录（手机验证码）。

## 第 10 步：三端联调 + 整体测试 + Bug 修复

完整走通业务流程：
1. Vue 后台：新增科室 → 添加医生 → 设置排班号源；
2. 鸿蒙端用户账号登录（验证码），新增就诊人，执行挂号预约 + 支付；
3. 验证数据库：生成挂号订单，排班剩余号源扣减；
4. 鸿蒙端取消预约，验证号源回退，订单状态变更；
5. Vue 后台查看预约订单，执行强制取消/退款审核；
6. 测试边界场景：号源为 0 禁止预约、未登录拦截、重复挂号拦截、超时未支付释放、逻辑删除、Redis 缓存、RocketMQ 消息、401 鉴权。
