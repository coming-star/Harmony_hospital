## 通用约定

1. **统一响应体**：所有接口返回 `ApiResponse<T>` = `{ "code": 200, "message": "操作成功", "data": T }`，`code=200` 成功，非 200 为业务错误码。
2. **分页响应体**：列表接口 `data` = `PageResult<T>` = `{ records: T[], total, page, size }`；分页参数 `page` 从 1 开始，`size` 默认 10。
3. **认证**：除注册/登录外，所有接口必须带请求头 `Authorization: Bearer <token>`：
   - 缺失 / 过期 / 已在 Redis 黑名单 → **401**（客户端清本地 Token 并跳登录页）
   - 角色不匹配（患者访问 `/api/admin/**`）→ **403**
4. **ID 传输**：雪花 ID 超过 JS 安全整数，后端一律以**字符串**返回（如 `"slotId": "2095770973474160642"`），前端原样回传，**禁止转数字**。
5. **金额**：一律整数**分**，字段名带 `Fen`（如 `feeFen: 3000` = ¥30），前端 `/100` 转元展示。
6. **时间格式**：日期时间 `yyyy-MM-dd HH:mm:ss`、纯日期 `yyyy-MM-dd`、纯时段 `HH:mm:ss`（Asia/Shanghai）。
7. **删除**：管理端删除一律逻辑删除（`deleted=1`）/ 启停（`enabled=0`），不做物理删除。

# 一、登录注册与认证鉴权（6 接口）

## 1.1 患者注册

- **接口地址**：`POST /api/app/auth/register`
- **认证**：否
- **请求体**：

| 字段       | 说明                      | 必须 | 示例            |
| -------- | ----------------------- | -- | ------------- |
| phone    | 手机号（11 位）               | 是  | `13800000008` |
| password | 密码（8\~64 位，BCrypt 加密存储） | 是  | `password`    |
| nickname | 昵称                      | 否  | `小王`          |

- **行为**：成功后自动登录，直接返回 `LoginResponse`（含 JWT）。
- **错误**：`409001` 手机号已注册；`400` 参数校验失败。

## 1.2 患者登录

- **接口地址**：`POST /api/app/auth/login`
- **请求体**：`{ "phone": "13800000002", "password": "password" }`
- **行为**：账号不存在与密码错误统一返回 401"账号或密码错误"（避免枚举用户）。
- **响应示例**：

```json
{
  "code": 200, "message": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "userId": "10002",
    "nickname": "测试用户",
    "userType": "PATIENT"
  }
}
```

## 1.3 患者登出

- **接口地址**：`POST /api/app/auth/logout`（需 Header `Authorization`）
- **行为**：当前 Token 的 `jti` 加入 Redis 黑名单直到自然过期；重复调用第二次起返回 401。

## 1.4 管理员登录

- **接口地址**：`POST /api/admin/auth/login`
- **请求体**：`{ "username": "admin", "password": "admin123" }`（默认账号见种子数据）。

## 1.5 管理员登出

- **接口地址**：`POST /api/admin/auth/logout`，行为同 1.3，需 ADMIN 角色。

## 1.6 查询当前登录用户

- **接口地址**：`GET /api/me`（患者/管理员通用）
- **响应**：`data = { userId, userType, jti }`。
- **用法**：App 冷启动先调此接口判断登录态，401 即跳登录页。

# 八、挂号记录管理（9 接口）

## 8.1 创建预约订单（患者端）

- **接口地址**：`POST /api/orders`
- **限流**：同一用户 **5 次/分钟**，超出返回 422001 提示"操作过于频繁"。
- **执行流程**：
  1. Redis 限流：`reg:limit:{userId}:{分钟}` 计数，超过 5 次/分钟直接拒绝
  2. Redis `SETNX` 分布式锁（`reg:lock:{就诊人}:{医生}:{日期}:{时段}`，30 秒过期），防同一就诊人对同一医生同一时段重复挂号
  3. 幂等键查重（`uk(user_id, idempotency_key)`），重试返回同一笔订单
  4. 乐观锁条件扣号源：`UPDATE schedule_slot SET remaining_quota = remaining_quota-1, version=version+1 WHERE id=? AND status='OPEN' AND remaining_quota>0 AND version=?`；影响行数 0 → `409003`（防超卖的数据库层兜底）
  5. 生成 `PENDING_PAYMENT` 订单，写 15 分钟支付截止期 `expiredAt`
- **请求体**：

| 字段             | 说明                                | 必须 |
| -------------- | --------------------------------- | -- |
| slotId         | 号源 ID（号源查询返回的 slotId，字符串）         | 是  |
| contactId      | 就诊人 ID（字符串）                       | 是  |
| idempotencyKey | 幂等键（客户端生成 UUID，同 key 重复提交只生成 1 笔） | 是  |

- **响应**：`data = OrderDetail`（status 固定 `PENDING_PAYMENT`，含 `expiredAt`）。
- **错误**：`404` 号源/就诊人不存在；`409003` 已约满；`422001` 限流。

## 8.2 模拟支付

- **接口地址**：`POST /api/orders/{id}/pay`
- **行为**：模拟支付渠道回调，`PENDING_PAYMENT → PAID`，写支付流水（channel=MOCK）与 `paidAt`；重复调用幂等。
- **错误**：`409004` 订单已取消；`404` 订单不属于当前用户。

## 8.3 取消订单（患者端）

- **接口地址**：`POST /api/orders/{id}/cancel`
- **行为**：待支付/已支付订单均可取消（已支付=退号），号源余号回补，`cancelReason=USER`。
- **错误**：`409004` 订单已终态（已取消/已完成）。

## 8.4 我的挂号记录

- **接口地址**：`GET /api/orders`
- **Query**：`status`（可选：PENDING\_PAYMENT/PAID/CANCELLED/COMPLETED）、`page/size`。
- **用途**：挂号记录页四个 Tab；响应 `PageResult<OrderDetail>`。

## 8.5 订单详情

- **接口地址**：`GET /api/orders/{id}`，响应 `OrderDetail`（字段见 8.9）。

## 8.6 后台 · 分页查询订单（ADMIN）

- **接口地址**：`GET /api/admin/orders/list`

# 九、AI 管家（1 接口）

## 9.1 AI 导诊对话

- **接口地址**：`POST /api/ai/chat`
- **说明**：后端以系统提示词（AI 导诊助手人设：推荐就诊科室、解答挂号与就诊流程问题、引导预约，遇急危重症提醒立即就医）拼接客户端传入的历史消息，以 OpenAI 兼容协议调用 DeepSeek（`deepseek-chat`，temperature 0.7，max_tokens 1024）。API Key 仅存后端环境变量 `DEEPSEEK_API_KEY`，未配置时返回"AI 服务未配置 API Key"。多轮上下文**由客户端每次携带完整消息列表**（服务端无状态、不落库；`ai_conversation` / `ai_message` 表为预留）。AI 仅作咨询和预约引导，**不能查询实时号源、不直接下单扣费**。
- **请求体**：

| 字段 | 说明 | 必须 |
| --- | --- | --- |
| messages | 消息数组，元素为 `{ "role": "user"\|"assistant", "content": "文本" }`，按时间正序 | 是 |

```json
{
  "messages": [
    { "role": "user", "content": "头疼应该挂什么科？" }
  ]
}
```

- **响应**：`data = { "reply": "头痛建议先挂神经内科……" }`。
