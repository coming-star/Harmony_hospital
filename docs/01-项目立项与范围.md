# 项目立项与范围

## 1. 项目概述

| 项目 | 内容 |
| --- | --- |
| 名称 | 东软云医院预约挂号系统 |
| 目标 | 让患者在鸿蒙 App 完成登录、就诊人管理、查询号源、预约及订单查询；让管理员维护基础医疗资源与挂号规则。 |
| 交付形态 | Spring Boot REST 服务、Vue 管理后台、HarmonyOS App、项目文档与演示数据。 |
| 周期 | 10 天：第 1 天环境搭建；第 2–8 天开发联调；第 9–10 天测试、答辩和面试准备。 |
| 团队 | 组长（兼测试/文档）、后端、Web 前端、鸿蒙端各 1 人。 |

## 2. 用户与权限

| 角色 | 权限边界 |
| --- | --- |
| 游客 | 浏览首页、科室和医生；注册、登录；访问 AI 管家时被引导登录。 |
| 患者 | 管理本人资料和就诊人；查询可预约号源；创建并支付/取消预约；查看本人订单；使用 AI 管家。 |
| 系统管理员 | 登录后台；维护用户、科室、医生、排班规则、挂号级别；查看并管理挂号记录和统计看板。 |

不设置医生端、真实诊疗、处方、医保结算、实时线下叫号和多院区分诊功能。本期不输出医疗诊断结论，AI 仅作信息咨询和预约辅助。

## 3. 范围与优先级

### P0：必须完成、可演示闭环

- 账号注册/登录、JWT 鉴权、退出；患者资料与多就诊人绑定。
- 三级科室展示（一级/二级，数据模型兼容多级）、医生/号别/排班维护。
- 未来 7 天可用号源计算、按日期和号别筛选、号源余量展示。
- 创建预约、锁定名额、防超卖、模拟支付、订单/挂号记录查询。
- 管理后台的登录、工作台和六类核心管理页面。

### P1：时间允许时完成

- 首页轮播、快速入口、搜索历史；订单取消及释放名额。
- AI 管家连续对话、按症状推荐科室、按条件查询医生、生成“待确认预约”草稿。
- RocketMQ 异步通知、预约超时取消、操作审计。

### P2：不纳入本次承诺

- 真实支付渠道、短信验证码、OCR/实名认证、医保及 HIS 对接。
- 大模型函数调用的完全自动下单；AI 不应直接完成扣费或绕过患者确认。

## 4. 关键业务约定

1. 一个账号可绑定多个就诊人；同一账号内身份证号唯一。身份证、手机号属于敏感信息，列表和日志必须脱敏。
2. 预约日期只能是从当天起 7 个自然日内的可放号日期；具体时段由排班生成。
3. 同一就诊人不得对同一医生、同一日期、同一时段、同一号别创建重复有效预约。
4. 余号扣减必须以服务端为准。创建订单时原子占用名额；未支付订单 15 分钟后自动取消并归还名额。
5. 本期支付是“模拟支付”：前端显式点击支付后，后端将订单改为已支付；接口保留支付渠道、流水号字段，便于替换真实网关。
6. 删除用户、科室、医生、号别、排班规则均为逻辑删除。被业务数据引用的基础数据禁止删除，应提示停用。
7. 已支付预约不可由患者直接取消；管理员可按演示规则取消，记录原因并释放尚未就诊的号源。

## 5. 成功标准

演示账号能在 App 从“选择科室 → 选日期/号别/医生/时段 → 选就诊人 → 模拟支付 → 我的挂号记录”走通；管理员修改排班或停用医生后，患者端的可预约结果正确变化；并发请求不能使余号为负或超出限额。
