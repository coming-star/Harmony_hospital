> 3. 所有数据模型（订单、就诊人、科室等）统一用块 A 中 `types/index.ets` 定义的类型，**页面中不重复定义 interface / 枚举字符串**。
> 4. 分支策略：块 A 分支 `feature/harmony-base`，合并至 `master` 后，B/C/D 分别开 `feature/harmony-b-entrance` / `feature/harmony-c-appointment` / `feature/harmony-d-mine`。每天至少 1 次提交，**每日 18:00 前 rebase master 并提合并请求**。

## 块 B — 入口三件套：登录 · 注册 · 首页（交付负责人：成员 B）

> **风格基础**：全部使用块 A 定义的颜色 / 字号 / 间距变量；按钮、输入框样式与 A 约定完全一致。

### 页面 1：登录页 `pages/auth/Login`
- 页面结构：**全屏品牌色渐变背景**（主色→辅色一）+ 中部半透明白色登录框

- **接口调用**：`api/auth.register({ phone, nickname, password })`；`409001` → 提示"该手机号已注册，请直接登录"并跳登录；成功直接进首页

## 块 C — 预约全流程（交付负责人：成员 C）

> **页面量最大、逻辑最复杂**，但最"线性"（一步一步推进）。建议优先级：**先做静态 UI 全流程** → 再从第一步开始接接口。

> **路由跳转参数约定**：科室 ID → 医生列表页；医生 ID + 日期 → 号源；slotId → 就诊人选择；slotId + contactId → 订单确认；orderId → 预约成功页。参数通过 router.push 的 params 传递，字段名用 `departmentId / doctorId / visitDate / slotId / contactId / orderId`，页面内不要自造名字。

### 页面 1：科室选择页 `pages/appointment/DepartmentSelect`
- 两栏布局：**左侧一级科室列表**（点击切换高亮，主色背景）/ **右侧二级科室卡片**（图标 + 科室名 + 医生数小标签）
- 数据：`GET /api/departments/tree`；左侧为一级科室（children 非空），右侧为选中一级的 children（二级）
- 点击二级 → 跳到医生列表页 + 传 `departmentId`

### 页面 2：医生列表页（含号源时段选择）`pages/appointment/DoctorList`
> 把"医生列表"和"时段选择"合为一页，避免 2 次跳转导致迷失。

- **顶部日期切换条**：未来 7 天横向滚动（今天/明天… + 星期 + 日期小圆），选中态主色填充；每切一次重新拉号源
- **医生卡片**（纵向列表）：头像 + 姓名 + 职称 + 所属科室 + 简介 → 下方展示当日号源时段按钮（`08:00-08:30 余3 ¥50` 这种）
- 数据：`GET /api/slots?departmentId=X&date=Y`（按医生 ID 聚合）；`remaining_quota=0` 的时段灰显、不可点
- 点时段按钮：如果当前用户没有任何就诊人 → 弹窗"请先添加就诊人"并跳转就诊人管理；否则直接下一步（传 slotId）

### 页面 3：就诊人选择页 `pages/appointment/ContactSelect`
- 单选 Radio 列表：每张卡片 姓名 + 关系（`RelationText`）+ 手机号
- 列表末尾 + 卡片**「新增就诊人」**：弹出一个半屏表单（`姓名 + 手机号 + 关系下拉`），调 `api/contact.createContact` 后自动刷新列表并选中新就诊人
- 右上角"管理" → 跳就诊人管理子页（块 D）
- 选中后点击「下一步」按钮 → 传 `slotId + contactId` 到订单确认页

### 页面 4：订单确认页 `pages/appointment/OrderConfirm`
- 展示"预约信息"大卡片：医院名（统一写「东软云医院」）+ 科室 + 医生 + 职称 + 就诊日期 + 时段 + 挂号级别 + 费用（¥ 元，用 FeeTag）
- 展示"就诊人"小卡片：姓名 + 关系 + 手机号
- **「确认支付」主按钮**：
  1. 本地生成 UUID 作为 `idempotencyKey`
  2. 调 `api/order.createOrder({ slotId, contactId, idempotencyKey })` → 得到 `orderId`
  3. 立即调 `api/order.pay(orderId)`（模拟支付，秒级成功）
  4. 成功 → 跳预约成功页 + 传 `orderId`；失败：`409003` 提示"号源已约满，请换时段"并返回上一页；限流提示"操作太快，请稍后重试"

### 页面 5：预约成功页 `pages/appointment/BookingSuccess`
- 大绿色对钩 ✔️ + 「预约成功！」
- 信息卡片：订单号 + 医院/科室/医生 + 就诊日期时段 + 就诊人姓名/电话
- **两个主按钮**（等高横排）：
  - 「查看挂号记录」→ 跳 `pages/mine/OrderRecord?tab=PAID`
  - 「返回首页」→ 路由跳 Tab「首页」
