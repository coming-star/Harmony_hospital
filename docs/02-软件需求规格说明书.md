# 软件需求规格说明书

## 1. 患者端功能需求

| 编号 | 模块 | 需求与验收口径 |
| --- | --- | --- |
| APP-01 | 注册登录 | 手机号+密码注册、登录；密码长度至少 8 位并加密保存；登录成功保存 JWT，失效后跳登录。 |
| APP-02 | 首页 | 展示搜索、轮播图、预约/挂号记录等快速入口。轮播图可先使用本地或后台固定配置。 |
| APP-03 | 预约科室 | 支持科室关键字搜索；展示一级科室及说明，展开二级科室；只显示已启用科室。 |
| APP-04 | 可用号源 | 选择二级科室后展示未来 7 日；按全部/号别筛选；仅展示当日有有效排班且余号大于 0 的医生时段。 |
| APP-05 | 预约下单 | 展示医生头像、姓名、科室、号别、时段、费用、余号；选择已绑定就诊人；确认后生成待支付订单。 |
| APP-06 | 支付与订单 | 模拟支付后订单变为已支付；我的页面可按状态查看订单详情。待支付可取消；超时自动关闭。 |
| APP-07 | 就诊人 | 新增、编辑、删除本人就诊人，字段为姓名、身份证号、手机号；有有效订单的就诊人不可删除。 |
| APP-08 | 我的 | 展示头像、昵称、挂号记录、就诊人绑定、设置及退出登录。 |
| APP-09 | AI 管家 | 未登录禁止会话；已登录可发送文本和查看有限历史；支持科室推荐、号源查询与生成预约草稿。任何下单必须由患者在预约页二次确认。 |

## 2. 管理端功能需求

| 编号 | 模块 | 需求与验收口径 |
| --- | --- | --- |
| WEB-01 | 登录与框架 | 管理员登录后进入左右布局后台；左侧导航，右侧路由内容；无权限路由不可访问。 |
| WEB-02 | 工作台 | 统计用户、科室、医生、今日预约数；提供快捷入口和系统/技术栈信息面板。 |
| WEB-03 | 用户管理 | 手机号、注册日期、最后登录、状态筛选；分页；新增/编辑/停用/逻辑删除；手机号唯一。 |
| WEB-04 | 科室管理 | 科室编码、名称、类型、父级、说明、生效标记；按名称与类型筛选、分页、新增编辑、逻辑删除。 |
| WEB-05 | 医生管理 | 维护姓名、所属科室、头像、职称/简介、挂号级别、排班规则、生效标记；支持筛选和逻辑删除。 |
| WEB-06 | 排班管理 | 维护排班说明、星期集合、上午/下午、时段规则、限额、启用状态；提供人类可读预览和规则串。 |
| WEB-07 | 挂号级别 | 维护编码、名称、费用、限额、排序和状态；编码唯一；删除前校验引用关系。 |
| WEB-08 | 挂号记录 | 按订单号、患者、就诊人、医生、日期、状态筛选；分页查看详情，必要时由管理员取消。 |

## 3. 订单状态机

```
待支付(PENDING_PAYMENT) --支付成功--> 已支付(PAID) --> 已完成(COMPLETED)
        |                         |
        +--用户取消/15分钟超时--> 已取消(CANCELLED)
                                  +--管理员取消--> 已取消(CANCELLED)
```

只有 `PENDING_PAYMENT` 占用号源；取消、超时和支付失败均须幂等地释放一次名额。`PAID` 状态由演示用支付成功接口产生；实际项目应接收支付平台签名回调。

## 4. 非功能需求

- 安全：密码使用 BCrypt；接口采用 Bearer JWT；角色鉴权；敏感字段脱敏；禁止在日志中写入密码、完整身份证、API Key。
- 性能：普通列表接口 P95 小于 1 秒；预约创建接口 P95 小于 2 秒（本地演示环境）。
- 一致性：余号不可为负；支付、取消回调可重试且结果幂等；所有写操作记录创建/更新时间与操作者。
- 可用性：统一异常码、加载/空态/失败提示；移动端网络失败可重试；关键表软删除。
- 兼容：后端 UTF-8、统一时区 `Asia/Shanghai`；时间以 ISO 8601 传输；金额用分（整数）存储和计算。

## 5. 页面导航

```
App：登录/注册 → 底部 Tab（首页 | 预约 | AI管家 | 我的）
预约：科室分类 → 日期与医生 → 预约挂号 → 支付 → 挂号记录
后台：登录 → 工作台 → 用户/科室/医生/排班/挂号级别/挂号记录管理
```
