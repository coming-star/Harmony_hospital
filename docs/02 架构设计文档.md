# 东软云医院挂号预约系统 · 架构设计文档

## 1. 架构模式

系统采用**前后端分离架构**：三端（鸿蒙用户端、Web 管理员端、统一后端服务）独立部署，前端不直接操作数据库，所有数据交互通过后端 RESTful 接口完成。

```
┌─────────────────────┐     ┌─────────────────────┐
│  鸿蒙用户端 APP      │     │  Web 管理员端        │
│  ArkTS + ArkUI       │     │  Vue3 + ElementPlus  │
└──────────┬──────────┘     └──────────┬──────────┘
           │        HTTPS / RESTful    │
           └────────────┬──────────────┘
                        ▼
              ┌─────────────────────┐
              │   后端服务            │
              │  SpringBoot 3 + JDK17│
              └──────────┬──────────┘
                         ▼
        ┌────────┬───────────────┬────────┐
        ▼        ▼               ▼        ▼
      MySQL 8   Redis          RocketMQ  （短信/支付对接）
```

## 2. 总体架构分层

### 2.1 客户端层（展示层）

| 端 | 技术 | 职责 |
|---|---|---|
| 鸿蒙用户端 | ArkTS + ArkUI | 页面渲染、用户交互、参数传递；预约、AI 管家、就诊人、我的预约 |
| Web 管理员端 | Vue3 + Element Plus + Axios | 后台数据管理页面展示与操作 |

客户端不承载业务逻辑与数据持久化，仅请求后端接口。

### 2.2 服务端层（业务层）

| 子层 | 职责 |
|---|---|
| Controller | 接收 HTTP 请求、参数校验、调用 Service、统一返回 `Result` JSON |
| Service | 核心业务逻辑：号源校验与预占、预约流程、支付/退款、状态机流转、事务控制 |
| Mapper | 对接数据库增删改查，基于 MyBatis-Plus 简化开发 |
| 通用配置 | 跨域、Redis、RocketMQ、JWT 鉴权、统一返回结果、全局异常、工具类 |

### 2.3 数据层（存储层）

| 组件 | 职责 |
|---|---|
| MySQL 8 | 持久化科室、医生、就诊人、排班、预约订单、支付流水等核心数据 |
| Redis | 缓存热点数据、登录 Token 与登录态、短信验证码 |
| RocketMQ | 异步：预约通知、**订单超时未支付释放**（延迟消息）、退款等 |

## 4. 关键机制设计

### 4.1 JWT 鉴权 + Redis 登录态

1. 登录成功签发 JWT（含 userId、role、过期时间），同时写 Redis（`login:token:{userId}`）；
2. JWT 拦截器校验 `Authorization: Bearer <token>` 的签名、有效期与 Redis 登录态；
3. 无 token / 失效 / 过期 → 401 未登录；公开接口（科室列表、医生列表、排班查询等）白名单放行；
4. 开发期拦截器默认关闭，后端全量完成后开启做鉴权回归。

### 4.2 号源防超卖（核心）

> 防超卖以**数据库条件更新 + 乐观锁兜底**为准，Redis 不承担扣减一致性。

三段式：
1. **下单预占**：事务内条件更新，仅当有可用号才预占：
   ```sql
   UPDATE schedule SET locked_num = locked_num + 1
    WHERE id = ? AND (remain_num - locked_num) > 0 AND deleted = 0;
   ```
   受影响行数 = 0 → 号源已满，下单失败。
2. **支付扣减**：支付成功后 `remain_num - 1`、`locked_num - 1`（同事务）。
3. **乐观锁兜底**：`schedule.version` 参与条件更新，防并发 ABA。

Redis 可选增强：`schedule:remain:{scheduleId}` 做查询层热点缓存与预检，最终一致性以 DB 为准。

### 4.3 超时未支付释放（RocketMQ 延迟消息）

1. 下单后发送延迟消息（如 15 分钟），携带 `orderNo`；
2. 消费端：订单仍为"待支付"→ 置为"已取消（超时未支付）"并释放预占；已支付/已取消 → 幂等忽略；
3. 与支付回调**竞态**：以订单当前状态为前提做幂等判断，用 `version` 乐观锁保证同一订单只被一种路径成功变更。

### 4.4 支付体系

| 环节 | 设计 |
|---|---|
| 下单 | 创建 `appointment`（待支付）+ 生成 `pay_order`（待支付） |
| 支付 | 用户端调起微信/支付宝 → 第三方回调 → 后端幂等校验 → 更新订单、扣减号源、生成排队号 |
| 超时 | RocketMQ 延迟消息自动释放（见 4.3） |
| 退款 | 取消已付订单 → 生成 `refund_log`（待审核）→ 审核/自动退 → 支付状态置已退款 |

### 4.5 Redis 缓存热点数据

- 科室两级列表、医生列表：变更时失效；
- 可约排班查询：以 `(deptId, date, slot, registerType)` 为 key 短时缓存；
- 短信验证码：`sms:code:{phone}`，5 分钟有效。

### 4.6 RocketMQ 异步通知

预约成功、取消、退款等事件发送消息，消费者异步处理通知，不阻塞主流程。

### 4.7 逻辑删除与唯一索引

- `deleted` 用 **bigint**：0=未删，软删时 `SET deleted = id`；
- 唯一索引统一为 `(业务键, deleted)`，软删后业务键可复用；
- 同一就诊人同一排班"防重复挂号"由**服务层规则**保证（DB 不设该唯一键，避免取消后无法重约）。

## 5. 工程目录结构

### 5.1 后端

```
hospital-backend
├─ src/main/java/com/neusoft/hospital
│  ├─ HospitalApplication.java        # 启动类 @MapperScan("com.neusoft.hospital.mapper")
│  ├─ config/                          # 跨域/MP/Redis/RocketMQ/Knife4j
│  ├─ common/                          # Result、全局异常、常量、工具类
│  ├─ security/                        # JWT 工具、拦截器（开发期注释关闭）
│  ├─ controller/                      # User/Department/Doctor/Schedule/Appointment/Patient/AI/Admin
│  ├─ service/ + impl/
│  ├─ mapper/
│  ├─ entity/                          # 对应各数据表
│  ├─ dto/ + vo/
│  └─ mq/                              # RocketMQ 消息与消费
└─ src/main/resources
   ├─ application.yml
   ├─ mapper/*.xml
   └─ sql/init.sql
```

### 5.2 Vue 管理员端

```
hospital-admin-web
├─ src/api/          # axios 封装 + 各模块 API
├─ src/views/        # login / dashboard / department / doctor / schedule / appointment / user
├─ src/router/ + src/store/
└─ src/utils/request.js   # 统一 baseUrl、token 头、Result 解析
```

### 5.3 鸿蒙用户端

```
hospital-patient-app
├─ entry/src/main/ets/
│  ├─ pages/          # Index / Appointment / AiAssistant / Mine / Login
│  ├─ api/            # 网络请求封装（模拟器 10.0.2.2:8080）
│  ├─ model/          # 数据模型
│  └─ common/         # 公共组件
```

## 6. 部署架构

```
鸿蒙模拟器(10.0.2.2:8080) ─┐
Vue(dev :5173 代理→:8080) ─┼─→ 后端(:8080) ─→ MySQL(:3306) / Redis(:6379) / RocketMQ(:9876)
```

- 后端端口 `8080`；Vue 开发经 Vite 代理转发；鸿蒙模拟器直连 `10.0.2.2:8080`；
- 生产可扩展为 Nginx 反代 + 前后端分离部署。

## 7. 非功能架构保障

| 维度 | 措施 |
|---|---|
| 性能 | Redis 缓存热点；异步化非核心链路；分页查询 |
| 一致性 | 预占/扣减同事务；乐观锁兜底；MQ 幂等消费 |
| 安全 | JWT 鉴权 + 数据权限隔离；BCrypt 密码；跨域白名单；参数校验 |
| 可维护 | 分层清晰；统一 Result/异常；Knife4j 在线文档 |
